用户在 ChatGPT iOS App 中点击 MP3 试听附件一直转圈，改发同一 MP3 的直接下载入口后仍未解决。随后将同一段音频转换为 M4A（AAC-LC），重新上传并交付新的附件链接；用户确认这一版可以播放。

## 为什么这版能播放

实际验证的是：更换容器和编码、设置前置索引并重新上传后，用户端恢复播放。AAC/M4A 是 iPhone 的常用播放格式；前置索引让 MP4 类容器更适合边下载边开始播放。

但这些变量同时改变，尚未做逐项对照实验。因此不能断言“唯一原因就是MP3不兼容”或“唯一原因就是索引位置”。MP3本身也可在iPhone播放，附件预览、缓存或传输状态可能参与此次故障。当前结论应写为“已验证有效的交付组合”，不是已证明的单一根因。

## 以后采用的交付规则

1. 给此用户交付独立试听音频时，优先生成 M4A：AAC-LC、44.1 kHz、双声道、128 kbps、+faststart。
2. MP3可保留为制作素材或备用文件；不要只重复发送已反馈转圈的同一入口。
3. 转换后检查非零大小、时长、编码、完整解码及moov位于mdat之前。
4. 重新上传新文件，提供普通可点击附件链接；不可仅改链接显示文字或改成图片语法后声称解决。
5. 文件通过ffprobe或ffmpeg检查，只能称“文件技术检查通过”；必须用户确认，或完成同端播放测试，才能称“手机端可播放”。
6. 如果同样的M4A组合也转圈，再检查附件下载、预览与传输环节，不能继续盲目转码。
7. AI经文朗读须明确标注“AI配音”，不可冒充真人原声。此次用户明确授权AI女声替代试听；批量采用哪种声线仍以用户试听反馈为准。

## 可复用转换命令

```bash
ffmpeg -y -i input.mp3 \
  -c:a aac -b:a 128k -ar 44100 -ac 2 \
  -movflags +faststart output.m4a

ffprobe -v error -show_entries stream=codec_name,profile,sample_rate,channels \
  -show_entries format=duration,size -of json output.m4a

ffmpeg -v error -i output.m4a -f null -
```

响度统一在转换前完成：目标约 -18 LUFS，真峰值不高于 -1.5 dBTP；不能靠提高峰值解决手机听感偏小。不要对经文末字进行硬截或用淡出压掉尾音。
